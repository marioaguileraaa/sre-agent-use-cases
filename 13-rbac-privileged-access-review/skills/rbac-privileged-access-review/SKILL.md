# Azure RBAC privileged access review

## Goal
Produce, read only, the inventory of privileged Azure RBAC role assignments in the configured subscriptions and classify each one into an actionable decision:

- **Remove · orphaned**: the identity no longer exists in Microsoft Entra ID.
- **Remove · redundant**: another permanent, unconditioned assignment of the same identity (or of a group it belongs to) already covers all its permissions at the same or a higher scope. Removing it does not change effective access.
- **Individual review**: current assignment with risk signals that its owner must validate.
- **Compliant**: current assignment without risk signals.

## Scope
- Azure RBAC role assignments visible from each configured subscription, including those inherited from Management Groups.
- Privilege tiers calculated from the role definition permissions (not only by name):
  - Tier 0 · Access control: can write role assignments (Owner, User Access Administrator, Role Based Access Control Administrator and custom equivalents).
  - Tier 1 · Full control: `*` on the control plane (Contributor and equivalents).
  - Tier 2 · Service admin: service administration roles (for example, Azure Kubernetes Service Cluster Admin, Key Vault Administrator).
- PIM state (active, activated or eligible), user and application sign-in activity, and group membership.
- Microsoft Entra ID directory roles and Microsoft Graph permissions are out of scope.

## Required tool
Use `generate-rbac-privileged-review` (0 parameters, `{}`).

## Security
- Read only: `Reader` on the subscriptions or Management Group and Microsoft Graph application permissions `User.Read.All`, `Application.Read.All`, `GroupMember.Read.All` and `AuditLog.Read.All` on the Azure SRE Agent managed identity.
- Never create, modify or delete role assignments, groups, identities or PIM eligibilities, even if the user asks for it in this conversation. Actions are executed outside the agent, through a change approved by people.
- Never show tokens or unfiltered Azure Resource Manager or Microsoft Graph responses.
- An authentication, permission or paging error is not a clean inventory: it is a blind spot and must be reported as partial coverage.

## Validation
Require and report:
- Inventoried assignments (`summary.total_role_assignments`) and privileged assignments (`summary.privileged_assignments`), with the breakdown by tier (`summary.by_tier`).
- Decisions (`summary.decisions`) and the Owner block (`summary.owner`: total, orphaned, redundant, review).
- Assignments that can be removed without changing effective access (`summary.removable_without_access_change`).
- Percentage of standing tier 0/1 access (`summary.standing_tier01_percent`) and PIM eligibilities (`summary.pim_eligible_privileged`).
- Coverage (`coverage.status` and the per-subscription and Graph detail). If it is `partial`, state exactly what could not be read.

## Output
Answer in the user's language:
1. The three files generated by the tool as clickable Markdown links, without recreating them or changing their design:
   - HTML report: `report_url` (and `report_path`).
   - CSV for Excel: `csv_url` (and `csv_path`).
   - JSON for approved automation: `json_url` (and `json_path`).
2. A 3–5 line executive summary with the Owner figures (total, removable, review) and the privileged totals.
3. A short table with the decisions and the main review signals (`summary.review_signals`).
4. The first 5 assignments of `top_review_items` (decision, role, identity, scope and action).
5. Coverage and, when applicable, **Required action** (missing permissions or failed reads).
6. At the end, an **Artifacts & links** section with the three links.
