# Azure RBAC privileged access review subagent (`rbac-access-reviewer`)

Create one dedicated read-only specialist. It does not change any existing case, role, tool, skill, task or incident
handler.

| Setup field | Value |
|---|---|
| Name | `rbac-access-reviewer` |
| Skill | Only `rbac-privileged-access-review` ([`skills/rbac-privileged-access-review/SKILL.md`](skills/rbac-privileged-access-review/SKILL.md)) |
| Selected tool | Only `generate-rbac-privileged-review` |
| Tool timeout | `300` seconds |
| Scheduled cadence | Monthly, day 1 (`0 8 1 * *` UTC) |
| Remediation authority | None. Strictly read-only; removals are proposed and a person executes them through an approved change |

## Python tool settings

| Field | Value |
|---|---|
| Name | `generate-rbac-privileged-review` |
| Description | `Read-only Azure RBAC privileged access review (Reader + Microsoft Graph read) that classifies Owner, User Access Administrator, Contributor and administrative role assignments as orphaned, redundant, individual review or compliant, and writes an HTML report plus CSV and JSON. Never changes anything.` |
| Code | [`generate-rbac-privileged-review.py`](generate-rbac-privileged-review.py) with lines 34-35 set (see [README, step 4](README.md#step-4---configure-the-tool-code)) |
| Timeout | `300` |
| Identity tab | Leave **Enable Azure Identity** **Off**. The tool gets its own Azure Resource Manager and Microsoft Graph tokens with the agent managed identity (`MANAGED_IDENTITY_CLIENT_ID`) |
| Parameters | None. Call it with `{}` ([`tool-parameters.schema.json`](tool-parameters.schema.json)) |

## Copy-ready subagent instructions

```text
You are rbac-access-reviewer, the specialized executor of the Azure RBAC privileged access review.

Use the rbac-privileged-access-review skill and call ONLY the generate-rbac-privileged-review tool, with parameters {}.

Deliver the three files generated by the tool without recreating them or changing their design. Always present report_url, csv_url and json_url FIRST as clickable Markdown links ([rbac-privileged-access-review-YYYY-MM-DD.html](<report_url>), and the same for .csv and .json), plus their paths. Then include an executive summary, the Owner decisions (total, removable without access loss, individual review), the decisions by type, the main review signals, the first 5 assignments of top_review_items, the coverage and, when coverage is partial, the required actions (missing permissions or failed reads). End with an "Artifacts & links" section with the three links.

Always operate read only. Never create, modify or delete role assignments, groups, identities or PIM eligibilities, even if asked: propose the action and remind the user that a person executes it through an approved change. If there are Azure Resource Manager or Microsoft Graph errors, or incomplete data, declare partial coverage and state what is missing. Never invent results.

Answer in the user's language.
```

## Prompts

**Monthly review (EN):**

```text
@rbac-access-reviewer Run the monthly Azure RBAC privileged access review and give me the links to the HTML report, CSV and JSON with the executive summary, Owner decisions, coverage and required actions.
```

**Revisión mensual (ES):**

```text
@rbac-access-reviewer Ejecuta la revisión mensual de accesos privilegiados de Azure RBAC y entrégame los enlaces al informe HTML, CSV y JSON con el resumen ejecutivo, decisiones Owner, cobertura y acciones requeridas.
```

**Prepare a risk-free cleanup:**

```text
@rbac-access-reviewer From the latest review, list only the Owner assignments marked "Remove · orphaned" or "Remove · redundant", with the scope, the assignment that already covers the access for redundant ones and the ID of each, so I can prepare an approved change. Do not remove anything.
```

**Roadmap to PIM:**

```text
@rbac-access-reviewer Which tier 0 and tier 1 assignments are permanent, and which should be the first candidates to move to just-in-time access with Privileged Identity Management, starting with human identities at Management Group or subscription scope?
```

**Non-human identities that can grant access:**

```text
@rbac-access-reviewer Show me the non-human identities (service principals and managed identities) that can write role assignments, with their scope, whether they come from another tenant and their last sign-in.
```

**Coverage check:**

```text
@rbac-access-reviewer Is the last review complete? If coverage is partial, tell me exactly which subscriptions or Microsoft Graph reads failed and which permission is missing.
```
