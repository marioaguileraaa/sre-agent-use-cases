# Daily relevant Azure changes digest subagent (`change-digest-reviewer`)

Create one dedicated read-only specialist. It does not change any existing case, role, tool, skill, task or incident
handler.

| Setup field | Value |
|---|---|
| Name | `change-digest-reviewer` |
| Skill | Only `azure-change-digest` ([`skills/azure-change-digest/SKILL.md`](skills/azure-change-digest/SKILL.md)) |
| Selected tool | Only `generate-azure-change-digest` |
| Tool timeout | `150` seconds (the tool keeps its own 100 s data-collection budget inside it) |
| Scheduled cadence | Daily, `0 18 * * *` UTC (19:00 in Madrid in winter; use `0 17 * * *` for 19:00 in summer) |
| Remediation authority | None. Strictly read-only; actions are suggested for a person to approve |

## Python tool settings

| Field | Value |
|---|---|
| Name | `generate-azure-change-digest` |
| Description | `Read-only daily digest of relevant Azure control-plane changes (Change Analysis in Azure Resource Graph, Reader): filters platform noise, scores deletes, exposure and security settings, SKU changes, new role assignments and Activity Log gap events (locks, diagnostic settings, policy, RBAC deletes), shows who / when / client and old -> new values, flags after-hours, first-time-actor and burst activity, and writes an offline HTML report, a JSON snapshot and two CSV files. Never changes anything.` |
| Code | [`generate-azure-change-digest.py`](generate-azure-change-digest.py) with the 2 placeholders of the `CONFIGURE` block replaced (README, step 3) |
| Timeout | `150` |
| Identity tab | Leave the switch **Off**. The tool authenticates with the agent managed identity itself (`MANAGED_IDENTITY_CLIENT_ID`) |

| Parameter | Type | Required | Description (paste as is) |
|---|---|---|---|
| `operation` | string | No | `report (default: HTML + JSON + changes CSV + property diffs CSV) or query (bounded chat view, no files).` |
| `period` | string | No | `Rolling window: last_24h (default), last_7d or last_14d (Change Analysis retention).` |
| `min_level` | string | No | `Lowest level listed in detail: high, medium (default) or low. Lower levels are still counted.` |
| `view` | string | No | `Only with operation=query: summary (default), relevant, deletes, security, actors, unusual, rbac, noise or coverage.` |
| `resource_group` | string | No | `Optional focus: resource group name or part of one (letters, digits, _ - . ( ), up to 90 characters). Empty = all.` |
| `limit` | int | No | `Only with operation=query: maximum rows, 1-100 (default 25); answers are capped to 3,500 bytes.` |

The same contract as JSON Schema: [`tool-parameters.schema.json`](tool-parameters.schema.json).

### Copy-ready subagent instructions

```text
You are change-digest-reviewer, the specialized executor of the daily relevant Azure changes digest.

Use the azure-change-digest skill and call ONLY the generate-azure-change-digest tool. For the daily digest call it with {"operation": "report", "period": "last_24h"}. For follow-up questions call it with operation "query" and the matching view: relevant, deletes, security, actors, unusual, rbac, noise, coverage or summary. Use period last_7d or last_14d for longer questions and resource_group to focus on one resource group. Never call it in parallel.

Deliver the four files generated by the report without recreating them or changing their design. Always present report_url, snapshot_url, changes_csv_url and diffs_csv_url FIRST as clickable Markdown links, plus their paths. Then give the headline, the counts, the high and medium items from top_items (what, where, who, when, why), deletes, security-relevant changes, new role assignments, Activity Log gap events, unusual activity and the coverage. End with an "Artifacts & links" section with the four links.

Always operate read only. Never create, modify, revert or delete resources, role assignments, locks, diagnostic settings or policies, even if asked: propose the action and remind the user that a person executes it through an approved change. Never infer intent or blame from a single field: quote changedByType, clientType, operation and correlationId. If coverage is partial, or a source is denied, failed or skipped, say what is missing and the required action. Never invent results.

Answer in the user's language (English by default).
```

## Scheduled daily automation (`0 18 * * *` UTC)

| Field | Value |
|---|---|
| Task name | `Azure Changes - Daily relevant changes digest` |
| Description | `Every day: read-only digest of the relevant Azure changes of the last 24 hours, with noise filtered out, deletes, security-relevant changes, new role assignments, Activity Log gap events and unusual activity.` |
| Response subagent | `change-digest-reviewer` |
| Frequency | Daily, at the end of your business day. The form uses your browser time zone: 19:00 in Madrid = 18:00 UTC in winter (CET), 17:00 UTC in summer (CEST) |
| Message grouping for updates | Use same chat thread |
| Agent autonomy | Autonomous (Default) |

Run it every day, weekends included: weekend changes are a signal in themselves.

### Scheduled task prompt

```text
@change-digest-reviewer Run the daily relevant Azure changes digest (operation=report, period=last_24h). Give me the links to the HTML report, the JSON snapshot and the two CSV files first, then the headline, the high and medium changes, deletes, security-relevant changes, new role assignments, Activity Log gap events, unusual activity and the coverage.
```
