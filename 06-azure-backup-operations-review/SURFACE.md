# Offline operations workpaper

**Scope:** emitted HTML in `generate-azure-backup-report.py`. **Mode:** Operate.
The analyst qualifies the requested window and source history, finds native
Backup errors/warnings, inspects original evidence and decides on human review.
No control performs a recovery, protection or incident action.

The brief-pinned yellow/charcoal workpaper opens with requested UTC boundaries
and unknown history before counts. Complete-file actions sit alongside that
qualification. The job ledger follows with vault/full-ID, job text, native
state, operation, window and item controls. Human review, current items,
history and source receipts remain independently navigable.

The signature interaction is inline original evidence, not a modal or hidden
recollection. Native list and later detail observations are both inspectable.
Item identity uses full native protected-item IDs; sourceResourceId and friendly
names never identify a child item. Unknown schedules and denominators remain
visible. Whole JSON/CSV downloads ignore filters and retain exact prepared bytes.

Desktop uses ruled ledgers. Mobile uses labeled records, stacked filters and
wrapped controls. Print expands disclosures and all matching job rows rather
than only a visible page. Keyboard skip/focus and semantic headings are required.

Synthetic preview captures remain offline checks only. Privacy-masked actual
report, saved SRE setup, normal delivery and manual monthly-task captures now
document separate dated executions. Unknown history is still explicit.
The generic package and masked captures are published privately, not deployed
or accepted in a new customer's environment. Recorded private preflight replay stays
historical source-shaped checking, never a fresh live run. The final UI capture
phase was expressly read-only and did not change this report or rerun a tool.
