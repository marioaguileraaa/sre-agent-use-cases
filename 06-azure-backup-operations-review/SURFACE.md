# Offline operations workpaper

**Scope:** emitted HTML in `generate-azure-backup-report.py`. **Mode:** Operate.
The analyst qualifies the requested window and source history, finds native
Backup errors/warnings, inspects original evidence and decides on human review.
No control performs a recovery, protection or incident action.

The brief-pinned yellow/charcoal workpaper, in the Azure SRE Agent report
family since 2026-11-12, opens with a slim bar (customer plaque, section links,
Read-only, Print / PDF) and a charcoal verdict band: the verdict, provenance,
reference and UTC-window chips, and the human-review queue by severity. KPI
cards for Failed, warnings, Backup and other records, observed items and the
Unknown denominator sit on its edge, followed by the unknown-history notice,
the UTC window beside the complete-file actions, prioritised next steps and
Backup records by native state. The job ledger follows with vault/full-ID, job
text, native state, operation, window, item and order controls. The human
review register (severity-ordered, filterable), current items, history and
source receipts remain independently navigable.

The signature interaction is inline original evidence, not a modal or hidden
recollection. Native list and later detail observations are both inspectable.
Item identity uses full native protected-item IDs; sourceResourceId and friendly
names never identify a child item. Unknown schedules and denominators remain
visible. Whole JSON/CSV downloads ignore filters and retain exact prepared bytes.

Desktop uses ledger rows with each record's evidence and full IDs on a
full-width line. Mobile uses labeled records, stacked filters and wrapped
controls. Print (A4 landscape) expands disclosures and all matching job rows
rather than only a visible page. Keyboard skip/focus and semantic headings are
required.

Synthetic preview captures remain offline checks only. Report views re-rendered
from the actual normal run's pseudonymized JSON, plus privacy-masked saved SRE
setup, normal delivery and manual monthly-task captures, document separate dated
executions. Unknown history is still explicit.
The generic package and masked captures are published privately, not deployed
or accepted in a new customer's environment. Recorded private preflight replay stays
historical source-shaped checking, never a fresh live run. The final UI capture
phase was expressly read-only and did not change this report or rerun a tool.
